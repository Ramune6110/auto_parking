# ドキュメント記載規約

## 1. この文書の目的

理論資料を読み進める順序と、図・数式・実装の対応を文書間で統一するためのルールです。新しい制御器やモデルの資料を追加するときも同じ形式を使用します。

## 2. 章構成

### 2.1 タイトル

- タイトルは内容を表す名詞句とし、`段階11`のようなロードマップ番号を含めません。
- 制御器資料は原則として「○○制御」、制約資料は「○○制約」、基礎資料は対象モデル・概念名を使用します。
- 段階番号は`learning_roadmap.md`と`index.md`の分類で管理します。

理論を説明する文書は、必要な範囲で次の順序を基本とします。

1. この章の目的
2. 使用する記号
3. 前提または幾何学的関係
4. 数式の導出
5. 数値例
6. 数式・図・ソースコードの対応
7. この章の確認ポイント
8. 現段階の限界

短いガイドや実験結果では、内容に不要な節を無理に追加しません。

## 3. 数式

- 表示数式はLaTeX形式の二重ドル記号で囲みます。
- 数式番号は文書ごとに式 (1) から連番にします。
- 数式には`\tag{1}`のように数字だけを指定します。
- 本文では「上式」だけで済ませず、「式 (3)」のように番号で参照します。
- 新しい記号は使用前に記号表または本文で定義し、物理量には単位を付けます。
- 近似、仮定、符号規約を省略せず、どの式から変形したかを説明します。

## 4. 図

- 図は各文書で図1から連番にします。
- 画像の直後に`**図1　説明**`の形式でキャプションを置きます。
- 本文で、図中の記号がどの数式番号に対応するかを説明します。
- 幾何学的導出では、点、角度、距離、正負方向を図中に表示します。
- 幾何図は`python/doc_figures/generate_doc_figures.py`で数値計算して生成します。
- Markdownは高解像度PNGを参照し、PDF生成用に同じ内容のSVGも保存します。
- 外部画像を使用する場合は、出典URL、著者・組織、ライセンス、参照日を画像直下へ記載します。
- 処理順序、分岐、フィードバックループ、モジュール間の受け渡しはMermaidを優先します。
- Mermaid図にも`**図1　説明**`形式のキャプションを付け、本文から図番号で参照します。
- 制御フロー図では入力、制御器、制約、適用値、車両モデル、次状態のフィードバックを省略しません。

## 5. 用語と表記

- `Pure Pursuit`、`Stanley`、`LQR`などの名称は文書内で表記を統一します。
- 横偏差は経路左側を正、方位誤差は「参照方位－車両方位」とします。
- 単位は`m`、`s`、`rad`、`m/s`のようにSI単位を基本とします。
- 英数字と日本語の間の空白は、数式やコードを除いて必要最小限にします。

## 6. ソースコードとの対応

- パスはプロジェクトルートからの相対パスで記載します。
- ヘッダーは`include/...`、実装は`src/...`まで省略せず記載します。
- 理論文書の末尾に、図・式・実装を対応付ける表を置きます。
- 実装と異なる一般理論を説明する場合は、その差を「現段階の限界」で明示します。

### 6.1 トレーサビリティID

- 理論式には`PP-EQ-10`のようなIDを付けます。接頭辞は文書、`EQ`の後ろは文書内の式番号を表します。
- Markdownでは式の直前に`<a id="pp-eq-10"></a>`を置き、式へ直接リンクできるようにします。
- C++の宣言・実装には`// Traceability: PP-EQ-10`、テストには`// Verifies: PP-EQ-10`を記載します。
- 数式を直接持たない処理には`IMPL-SIM-01`のような処理IDを使用します。
- 1行の計算を逐語的に説明せず、関数または意味のまとまりに対してIDを記載します。
- 全体の対応は[理論・数式・ソースコード トレーサビリティ](traceability.md)を正とします。

## 7. 文字コードと表示確認

- MarkdownとSVGはUTF-8で保存します。
- 文字化けを示すUnicode置換文字`U+FFFD`や、意図しない制御文字を含めません。
- `\frac`、`\operatorname`、行列の改行`\\`などのLaTeXコマンドを確認します。
- 相対リンクと画像パスが実在することを確認します。

## 8. 理論図の再生成

プロジェクトルートで次のコマンドを実行します。

```powershell
python python/doc_figures/generate_doc_figures.py
```

MatplotlibとNumPyを使用し、`docs/figures`へ同名のPNGとSVGを生成します。図を直接編集せず、幾何条件、ラベル位置、配色は生成スクリプト側で変更してください。

図の幾何条件と生成漏れはCTestの`documentation_figures_test`で確認します。Pure Pursuitでは$CP=CT=R$、接線と半径の直交、弦長、曲率式を数値検証しています。

式アンカー、ソースコード参照、未定義IDはCTestの`traceability_test`で検査します。式を追加した場合は次を実行してアンカーを生成します。

```powershell
python python/check_traceability.py --apply-anchors
```
